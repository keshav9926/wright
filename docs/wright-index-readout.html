The thesis

An edge is only as good as its proof

Call resolution is undecidable in the general case, so the honest move is to grade it. Every edge carries how it was proven. Here is how globstar's 2,933 call sites actually landed.

That 2,424 is not a failure — it is the point. Almost all of it is calls into tree-sitter, fmt and the standard library, which are genuinely outside this repo's graph. A missing edge under-reports; a wrong edge poisons every query built on top of it. So the tool marks what it cannot prove and moves on.

What the readout led to

Two interfaces, and a bug behind one of them

wi symbols --kind interface said globstar has exactly two extension points, and ScopeBuilder is the one that matters for anything needing to know what a name refers to. Reading the scope tree it builds turned up a one-line inversion in analysis/scope.go: 

// Scope.AstNode is documented as:
//   "the AST node that introduces this scope into the scope tree"

nextScope := scope
if builder.NodeCreatesScope(node) {
    nextScope = NewScope(scope)
    scopeOfNode[node] = nextScope
    if scope != nil {
        scope.Children = append(scope.Children, nextScope)
        scope.AstNode = node   // ← sets the PARENT's node
    }
}

The new scope's own AstNode is never assigned, so it stays nil for every scope in the tree. Meanwhile the parent's gets overwritten by whichever scope-creating child happens to be visited last.

  • Every non-root scope reports AstNode == nil
  • A function scope ends up pointing at its own body block
  • A block with two sibling scopes keeps only the second

It's latent today — nothing in-tree reads the field yet — but it is a public field on a public type, documented with a meaning it does not have. The fix is one line: assign nextScope.AstNode, not scope.AstNode.
